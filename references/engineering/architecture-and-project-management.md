# 项目管理、模块化架构与设计模式实践

确保全栈工程在持续迭代中保持**可扩展性、低耦合度、可管理性与高可读性**。原则：**先满足当前真实约束下的清晰边界，用简单恰当的设计模式解决已知变化点，不为假想的未来过度设计。**

## 1. 可管理性与仓库结构

推荐按职责与依赖方向组织工程目录，保证模块边界在构建系统（CMake `target`）层面就被强制隔离：

```text
project-root/
├── include/<pkg>/        # 仅放对外稳定公共头文件（契约与接口，不含实现细节）
├── src/                  # 私有源码与内部头文件（app / domain / infra 按子目录隔离）
├── apps/                 # 组合根（Composition Root）：装配服务、UI/CLI 入口与配置加载
├── tests/                # 单元测试与集成测试（镜像 src 模块结构）
├── docs/adr/             # 轻量架构决策记录（ADR）：记录关键技术栈与接口取舍原因
├── cmake/                # 独立 Find/Options/Sanitizer 模块
├── CMakeLists.txt
├── CMakePresets.json
└── vcpkg.json
```

- **严格单向依赖**：`表现层 / 网络传输层（Qt / Web / HTTP / gRPC）` → `应用编排层（UseCase / Controller）` → `核心领域层（纯 C++ 规则与实体，不依赖 UI/DB/HTTP 框架）` ← `基础设施适配层（SQLite / PG / 文件 / 第三方 SDK）`。
- **可追溯变更**：涉及协议、数据格式、核心边界或工具链重大调整时，在 `docs/adr/` 用一页短文记录「背景 / 备选 / 决定 / 后果」，避免后续接手误回退。

## 2. 低耦合与可扩展性准则

1. **组合优于继承，面向接口编程**：核心服务通过纯虚接口（如 `INoteRepository`、`IClock`）与外部存储/网络解耦；业务层只依赖抽象接口，实现由基础设施层提供，**测试时可无缝替换内存替身或隔离测试库**。
2. **构造函数依赖注入（DI），拒绝全局可变单例**：把依赖作为构造函数参数显式传入（`std::unique_ptr` 或非拥有引用/接口指针），在 `apps/` 组合根统一装配。全局单例会隐藏真实依赖、破坏线程安全并导致并行单元测试相互污染。
3. **跨边界强制 DTO 转换**：禁止把数据库实体、JSON 文档、Protobuf 消息或 Qt Model 直接当成核心领域对象一路穿透全栈；在接口边界显式映射为干净的领域类型。
4. **隐藏实现细节（Pimpl / 私有静态目标）**：对外发布的库或大型组件通过接口抽象或 Pimpl 隔离第三方头文件，避免修改实现或升级依赖导致全仓库大面积重编译与 ABI 破坏（详见 [C++ 规范与 ABI](../workflow/cpp-standards-and-abi.md)）。

## 3. 可读性与代码卫生

- **单一职责，禁止上帝类与万能杂物文件**：类或模块超过 ~300–500 行、函数超过 ~50 行或嵌套超过 3 层时，按独立子步骤拆分或使用早返回（Guard Clauses）；禁止新建 `utils.h` / `common.h` 收集毫不相干的杂项函数。
- **消除布尔参数汤与魔法值**：禁止超过 1 个布尔参数的签名（如 `connect(host, true, false, true)`）；改用语义 `enum class` 或具名配置结构体（`ConnectOptions{ .useTls = true, .timeoutMs = 5000 }`）。
- **显式失败语义**：所有可恢复错误（文件、网络、用户输入、DB 约束）用清晰的返回类型（`Result<T, Error>` / `std::expected`（C++23；C++20 工程可用自定义 `Result<T, E>` 或 `tl::expected`）/ 错误码）或明确记录的异常边界处理；**严禁空 `catch (...) {}` 静默吞异常**。

## 4. 务实设计模式速查（仅在解决真实痛点时引入）

| 模式                       | 解决的耦合/扩展痛点                                          | 现代 C++ 推荐落地方式                                                           | 警惕过度设计（反模式）                                               |
| -------------------------- | ------------------------------------------------------------ | ------------------------------------------------------------------------------- | -------------------------------------------------------------------- |
| **RAII / ScopeGuard**      | 异常或早返回路径的资源、锁、事务泄漏                         | `std::unique_ptr`（配自定义 deleter）、`std::scoped_lock`、`QSaveFile`          | 裸手写到处分散的成对 `open()`/`close()` 清理分支。                   |
| **Strategy / Policy**      | 算法、校验规则、序列化或重试策略需动态/静态切换              | 闭合零开销用模板策略/Concepts；运行期切换用轻量 `std::function` 或小虚接口      | 只有一种固定实现却强行包一层空接口与配置文件切换。                   |
| **Factory / Builder**      | 隐藏复杂对象创建、多子类装配或参数合法性构建                 | 工厂函数返回 `std::unique_ptr<Interface>`；Builder 在 `.build()` 统一校验不变式 | 为普通简单值 struct（聚合初始化即可）强写冗长 Builder。              |
| **Repository + Adapter**   | 隔离第三方 SDK / SQLite / PG / HTTP 客户端变更对业务层的冲击 | 领域层定义 `IRepository`，适配层封装具体库并把库异常转成业务错误                | 把 SQL 语法或第三方 SDK 错误码直接泄露给上层 UI/业务判断。           |
| **Observer / Signal-Slot** | 一对多事件解耦（状态变化通知多处视图/日志）                  | Qt 用信号槽（带上下文与代次防过期）；纯 C++ 用轻量回调列表或订阅 token          | 形成环状事件链互相触发、无注销机制导致悬空通知。                     |
| **Command**                | 需要撤销/重做（Undo/Redo）、操作队列、宏录制或异步任务排队   | 封装 `execute()`/`undo()` 或结合 `QUndoCommand`（如画布/编辑器）                | 简单 CRUD 按钮也套一层 Command 工厂增加间接层级。                    |
| **State**                  | 对象生命周期存在多状态且转移条件复杂（连接状态、向导步骤）   | 闭合状态用 `std::variant<Idle, Connecting, Connected, Failed>` + 显式转移函数   | 用 5 个互相耦合的 `bool isConnecting, isError, ...` 拼凑非法组合态。 |
| **Pimpl**                  | 保持库二进制 ABI 稳定、隐藏私有成员并大幅降低头文件编译耦合  | 类内仅持 `std::unique_ptr<Impl> m_impl;`（在 `.cpp` 定义析构函数）              | 内部不对外发布的小型值对象无故多加一层堆分配。                       |
